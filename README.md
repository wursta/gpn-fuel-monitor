# GPN Fuel Monitor

Мониторинг наличия бензина на АЗС «Газпромнефть» через внутренний API с уведомлениями в Telegram.

## Возможности

- Периодическая проверка наличия топлива на указанной АЗС
- Поддержка нескольких видов топлива (конфигурируется)
- Определение статуса: «в наличии», «нет», «в пути», «неизвестно»
- Уведомления в Telegram при изменении статуса
- Уведомления о запуске/остановке монитора
- Сохранение состояния между запусками (state.json)
- Логирование в файл и stdout
- Автоочистка старых логов (по времени и размеру)
- Graceful shutdown по SIGINT/SIGTERM

## Требования

- Go 1.21+

## Установка

```bash
# Клонировать репозиторий
git clone <repo-url>
cd gpn-fuel-monitor

# Установить зависимости
go mod tidy
```

## Настройка

1. Скопируйте пример конфигурации:

```bash
cp config.yaml.example config.yaml
```

2. Отредактируйте `config.yaml` (пример в `config.yaml.example`):

```bash
cp config.yaml.example config.yaml
```

Полный пример конфига — см. `config.yaml.example`.

### ID топлив

| Топливо | ID |
|---------|-----|
| АИ-95 | 12 |
| G-Drive 95 | 421 |

Чтобы добавить новый вид топлива, просто добавьте его в секцию `fuels` в `config.yaml`.

### Получение токена Telegram

1. Напишите `@BotFather` в Telegram
2. Отправьте `/newbot` и следуйте инструкциям
3. Скопируйте токен бота
4. Чтобы получить chat_id, отправьте сообщение боту и откройте:
   `https://api.telegram.org/bot<TOKEN>/getUpdates`

## Логика определения статуса

| Условия | Статус |
|---------|--------|
| `avail == true` | в наличии |
| `avail == false && delivery == "no"` | нет |
| `avail == false && delivery == "yes"` | в пути |
| иначе | неизвестно |

## Автоочистка логов

При каждом запуске приложение проверяет `monitor.log`:

| Параметр | По умолчанию | Описание |
|----------|-------------|----------|
| `log_retention_days` | 7 | Если лог старше — обрезается |
| `log_max_size_mb` | 10 | Если лог больше — ротируется |

**Почему 7 дней:** при проверке каждые 5 минут за неделю накапливается ~2000 записей (~300 КБ) — достаточно для отслеживания тенденций, но не разрастается.

## Файлы, создаваемые при работе

- `state.json` — текущее состояние всех топлив (для сравнения изменений)
- `monitor.log` — журнал работы приложения
- `monitor.log.old` — временный файл при ротации лога

## Прокси

Для обхода блокировок Telegram API задайте прокси в `config.yaml`:

```yaml
proxy: "http://user:pass@proxy.example.com:8080"
```

Прокси используется для всех внешних запросов: Telegram API и API АЗС.

## Остановка

```bash
# По PID
kill <pid>

# Или Ctrl+C при запуске в терминале
```

При graceful shutdown состояние сохраняется в `state.json`.

## Запуск через Docker

### Требования

- Docker и Docker Compose v2

### Настройка

1. Скопируйте пример конфигурации (если ещё не сделали):

```bash
cp config.yaml.example config.yaml
```

2. Отредактируйте `config.yaml`:

   - Укажите `state_file` и `log_file` с путями к смонтированному тому:

     ```yaml
     state_file: "/app/data/state.json"
     log_file: "/app/data/monitor.log"
     ```

   - Заполните `telegram_bot_token` и `telegram_chat_id`
   - При необходимости укажите `proxy`

3. Запустите:

```bash
docker compose up -d
```

4. Просмотр логов:

```bash
docker compose logs -f
```

5. Остановка:

```bash
docker compose down
```
