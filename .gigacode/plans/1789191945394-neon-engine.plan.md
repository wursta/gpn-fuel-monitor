# План: GPN Fuel Monitor (Go)

## Цель
Мини-проект на Go для мониторинга наличия бензина на АЗС «Газпромнефть» через внутренний API с уведомлениями в Telegram.

## Архитектура

```
gpn-fuel-monitor/
├── go.mod              # Модуль gpn-fuel-monitor, Go 1.21+
├── go.sum
├── main.go             # Точка входа, graceful shutdown, главный цикл
├── config.go           # Загрузка config.yaml (gopkg.in/yaml.v3)
├── api.go              # GET-запрос к API, парсинг JSON
├── status.go           # getFuelStatus(f Fuel) -> string
├── state.go            # Чтение/запись state.json
├── telegram.go         # Отправка уведомлений в Telegram (с retries)
├── config.yaml         # Конфигурация
├── state.json          # Состояние (создаётся автоматически)
├── monitor.log         # Лог-файл (создаётся автоматически)
└── README.md           # Инструкция по сборке и запуску
```

## Шаг 6: status.go — Определение статуса

```go
func getFuelStatus(f Fuel) string {
    if f.Rest.Avail {
        return "в наличии"
    }
    if !f.Rest.Avail && f.Rest.Delivery == "no" {
        return "нет"
    }
    if !f.Rest.Avail && f.Rest.Delivery == "yes" {
        return "в пути"
    }
    return "неизвестно"
}
```

## Шаг 8: telegram.go — Уведомления

- Функция `SendTelegramNotification(token, chatID, message string) error`
- Эндпоинт: `https://api.telegram.org/bot{token}/sendMessage`
- POST с JSON body:
  ```json
  {"chat_id": "...", "text": "...", "parse_mode": "HTML"}
  ```
- Функция `SendWithRetry(token, chatID, message string, maxRetries int, delaySec int) error`
  - До 3 попыток с паузой 10 секунд
  - Логирование каждой попытки
  - Возврат последней ошибки

## Шаг 9: main.go — Главный цикл и graceful shutdown

- Инициализация логгера (двойной writer: `os.Stdout` + файл)
- Загрузка конфига
- Загрузка состояния
- Запуск главного цикла:
  ```go
  ticker := time.NewTicker(interval)
  defer ticker.Stop()

  // Первый запуск сразу
  checkAndNotify(cfg, state)

  for {
      select {
      case <-ctx.Done():
          log.Info("shutdown requested")
          return
      case <-ticker.C:
          checkAndNotify(cfg, state)
      }
  }
  ```
- `checkAndNotify()`:
  1. `FetchStationStatus(cfg)` → `[]Fuel`
  2. Для каждого топлива из `cfg.Fuels`:
     - Найти элемент по ID в `[]Fuel`
     - Вычислить `getFuelStatus(f)`
     - Сравнить с предыдущим состоянием через `StatusChanged()`
     - Если изменилось — сформировать сообщение, отправить через `SendWithRetry()`
     - Обновить `state.Fuels[fuelID]`
  3. `SaveState(cfg.StateFile, state)`
- Обработка ошибок:
  - API недоступен → лог ERROR, пропустить итерацию
  - Топливо не найдено → лог WARN
  - Ошибка парсинга → лог ERROR, пропустить
  - Скрипт НЕ падает
- Graceful shutdown:
  ```go
  sigChan := make(chan os.Signal, 1)
  signal.Notify(sigChan, syscall.SIGINT, syscall.SIGTERM)
  ctx, cancel := context.WithCancel(context.Background())
  defer cancel()
  go func() {
      <-sigChan
      log.Info("received signal, shutting down")
      cancel()
  }()
  ```

## Шаг 11: Автоочистка логов

### Конфигурация

Добавить в `config.yaml`:
```yaml
# Автоочистка логов
log_retention_days: 7
log_max_size_mb: 10
```

**Оптимальные значения по умолчанию:**
- `log_retention_days: 7` — за 7 дней при проверке каждые 5 мин ~2000 записей (~300 КБ), достаточно для отслеживания тенденций
- `log_max_size_mb: 10` — защита от разрастания при сбоях

### Изменения в config.go

Добавить поля в структуру `Config`:
```go
type Config struct {
    // ... существующие поля ...
    LogRetentionDays   int    `yaml:"log_retention_days"`
    LogMaxSizeMB       int    `yaml:"log_max_size_mb"`
}
```

Валидация: `log_retention_days >= 1` (по умолчанию 7), `log_max_size_mb >= 1` (по умолчанию 10).

### Новый файл: log_cleanup.go

Функции:

1. `CleanOldLog(logFile string, retentionDays int) error`
   - Проверяет age log-файла через `os.Stat().ModTime()`
   - Если файл старше `retentionDays` дней — обрезает до пустого (`os.Truncate`)
   - Логирует действие

2. `RotateLogIfTooLarge(logFile string, maxSizeMB int) error`
   - Проверяет размер файла через `os.Stat().Size()`
   - Если больше `maxSizeMB * 1024 * 1024` — ротация:
     - Переименовывает в `{logFile}.old`
     - Создаёт новый пустой файл
   - Логирует действие

3. `EnsureLogCleaned(logFile string, retentionDays, maxSizeMB int) error`
   - Вызывает обе проверки

### Изменения в main.go

Вызвать `EnsureLogCleaned` сразу после загрузки конфига, перед запуском основного цикла:
```go
if err := EnsureLogCleaned(cfg.LogFile, cfg.LogRetentionDays, cfg.LogMaxSizeMB); err != nil {
    logger.Warn("failed to clean old logs", "error", err)
}
```

## Ключевые решения

| Решение | Обоснование |
|---------|-------------|
| `log/slog` вместо `log` | Современный стандарт, группировка атрибутов |
| Сравнение по `(avail, delivery, since)` | Исключает ложные уведомления при внутренних изменениях API |
| Graceful shutdown через context | Корректное завершение, сохранение состояния |
| `gopkg.in/yaml.v3` | Стабильная библиотека для YAML |
| Повторные попытки Telegram (3x) | Telegram API может быть временно недоступен |
| Модульная структура (6 файлов) | Разделение ответственности, удобство поддержки |

## Шаг 12: Системные уведомления в Telegram

### Изменения в telegram.go

Добавить функции:

1. `SendSystemNotification(token, chatID, message string) error`
   - Обёртка над `SendWithRetry` для системных сообщений
   - Использует 3 попытки с паузой 5 секунд (быстрее, чем для статусов)

### Изменения в main.go

**При старте** (после загрузки конфига и логгера, но до основного цикла):
```go
if cfg.TelegramBotToken != "" && cfg.TelegramChatID != "" {
    msg := fmt.Sprintf("🟢 Монитор запущен\nАЗС %d", cfg.StationID)
    if err := SendSystemNotification(cfg.TelegramBotToken, cfg.TelegramChatID, msg); err != nil {
        logger.Warn("failed to send startup notification", "error", err)
    }
}
```

**При остановке** (в case `<-ctx.Done()`):
```go
if cfg.TelegramBotToken != "" && cfg.TelegramChatID != "" {
    msg := fmt.Sprintf("🔴 Монитор остановлен\nАЗС %d", cfg.StationID)
    if err := SendSystemNotification(cfg.TelegramBotToken, cfg.TelegramChatID, msg); err != nil {
        logger.Warn("failed to send shutdown notification", "error", err)
    }
}
```

### Формат сообщений

- Старт: `🟢 Монитор запущен\nАЗС {station_id}`
- Остановка: `🔴 Монитор остановлен\nАЗС {station_id}`
