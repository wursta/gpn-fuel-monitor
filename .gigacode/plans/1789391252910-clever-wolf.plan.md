# Docker Integration Plan

## Цель
Реализовать сборку и запуск gpn-fuel-monitor через Docker Compose.

## Артефакты

### 1. `Dockerfile` — multi-stage build
- **Build stage:** `golang:1.27` (bookworm если alpine нет) → `CGO_ENABLED=0 go build -ldflags="-s -w"`
- **Runtime stage:** `alpine:3.20` + `ca-certificates` + `tzdata`
- Non-root user (`appuser`)
- Без `EXPOSE` (background daemon)
- `ENTRYPOINT ["/app/gpn-fuel-monitor"]`

### 2. `docker-compose.yml`
- Service `gpn-fuel-monitor`
- Volumes:
  - `./config.yaml:/app/config.yaml:ro` — конфиг (bind mount)
  - `data:/app/data` — state.json + monitor.log (named volume)
- `working_dir: /app`
- `TZ=Europe/Moscow`
- `restart: unless-stopped`
- Resource limits: 0.5 CPU / 128MB RAM

### 3. `.dockerignore`
- `.git`, IDE files, runtime data (`state.json`, `monitor.log`), build artifacts, Docker файлы

### 4. Обновление `README.md`
- Секция с инструкцией по запуску через Docker
- Требование указать `state_file` и `log_file` в config.yaml как `/app/data/...`
- Таблицы томов, переменных окружения, ограничений

## Ключевые решения

| Решение | Обоснование |
|---------|-------------|
| Config mount ro | Конфиг не меняется внутри контейнера |
| Named volume для данных | state.json и monitor.log persist между перезапусками |
| Non-root user | Безопасность |
| Без EXPOSE | Нет HTTP-сервера, daemon process |
| Alpine runtime | Минимальный размер образа |

## Верификация

1. `docker compose build` — билд без ошибок
2. `docker compose up -d` — контейнер запущен
3. `docker compose logs -f` — мониторинг логов
4. `docker compose down && docker compose up -d` — persist state.json
5. `docker image ls` — размер образа < 50MB
